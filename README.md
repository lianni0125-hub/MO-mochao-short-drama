# 墨潮 · AI 短剧自动编剧系统

本地优先的中文短剧创作工作台。它把故事策划、人设、卡点、分集梗概、小说中间稿、可拍摄剧本、质量验收和跨集连续性组织成可审批、可编辑、可续跑的工程流程。

## 当前流程

1. 灵感孵化
2. 故事策划：标题、框架、世界观、故事梗概、核心期待
3. 人物人设与形象参考
4. 卡点与硬约束
5. 分集梗概：本集内容、钩子、必须发生、不得揭示
6. 分级写作：小说中间稿 → 剧情安排 → 可拍摄剧本 → 剧情记忆提炼

## 已实现

- 策划整体生成、单项重写、手动编辑与审批
- 人物卡新增、编辑、删除和补充生成；MiniMax 生图、提示词重生成与手动上传
- 卡点方案、硬约束、分集梗概、钩子、必须发生链与不得揭示
- 强烈/异常强烈情绪档位、第一/第三人称选择，小说中间稿与短剧剧本分阶段生成
- 单集生成、一键写完全本、从指定集重新写；后台任务不随页面切换中断
- 任务历史、分步耗时、错误类型、自动续跑次数与手动继续
- 并行工作台：保留原有全局 FIFO 串行模式；开启后支持跨项目并行、1–3 个动态并发、最多 10 个活动任务和项目级任务隔离
- 格式、篇幅、可拍摄性、必须发生/不得揭示质检
- 项目级向量剧情记忆：剧情事件链、最近事件、人物关系、实名次要人物、金手指与已验证能力、重要道具、资源账本
- 时间脉络：精确、相对、模糊、持续、倒叙、未来预示和平行时间关系
- 剧情记忆从最终剧本提炼；支持单集重新提炼和按连续集数重建向量/剧情链
- DOCX 模板分析、结果复核编辑、项目级切换与非默认模板删除
- 按集数导出分集梗概、小说或剧本 DOCX；剧本导出支持人物表格与形象参考图
- 项目拖动排序、项目回收站与 7 天后自动清理
- Market / Reality 资料库、手动录入、RSS 更新和历史快照

## 模型与 Embedding

正文生成支持 OpenAI Responses API，以及 MiniMax、智谱、DeepSeek、通义千问、Kimi 和自定义 OpenAI-compatible API。界面可保存各供应商的 Key，并单独测试生成与 Embedding 连接。

Embedding 用于剧情记忆建库与语义召回，支持 Google Gemini、MiniMax `embo-01`、OpenAI、智谱、通义千问和自定义接口。未配置 Embedding 时，不依赖向量的策划、人设、模板、保存和导出等功能仍可使用；涉及记忆提炼或向量召回的流程会要求先配置。

## 启动

要求 Node.js 25 或更高版本（项目使用 Node 自带 SQLite）。

```powershell
cd 'D:\codex专用 文件夹\ai-short-drama-writer'
npm install
npm start
```

打开 <http://127.0.0.1:3210>。也可运行 `scripts/start.ps1`。

## 配置

推荐在“模型设置”中分别配置并测试正文生成 API 和 Embedding API。也可复制 `.env.example` 为 `.env` 后手动填写。Key 只保存在本机 `.env`，该文件已被 Git 忽略。

## 数据与 Git 边界

- SQLite 与项目内容：`data/short-drama.db`
- 导入文件：`data/uploads/`
- 导出文档：`data/exports/`
- 密钥：`.env`

以上运行数据默认均不提交到 GitHub。GitHub 保存的是程序源码和版本记录，不是本地创作内容备份。

## 后台任务与并行

默认关闭并行，所有后台任务沿用全局 FIFO 顺序逐个执行。开启“并行工作台”后，不同项目可以同时生成；同一项目仍只允许一个运行中或排队任务，避免小说、剧本和剧情记忆互相覆盖。

- 工作台最多容纳 10 个当前任务。
- 实际并发限制为 1–3 个，可自动调节或手动固定。
- 自动模式遇到限流、超时或连接压力时会临时降低并发，稳定后逐步恢复。
- 关闭并行会安全中断当前工作台任务；已保存的阶段结果和检查点保留，可回到各项目任务列表继续或重试。
- 应用刷新或重启不会被当作用户关闭并行，支持从已有检查点恢复。

## 自动更新与测试

```powershell
npm run update:sources
npm test
```

可用 `scripts/install-daily-update-task.ps1` 注册 Windows 定时更新。电脑关机时不会运行；恢复运行后可补跑。

## 重要边界

- 导入 DOCX 的正文只作为数据和模板，不作为系统指令执行。
- 02 故事策划与 03 初始人设是结构化主输入；跨集连续性由项目级剧情记忆管理。
- 04 硬约束用于 05 剧情规划，不混入动态剧情记忆。
- 06 以“必须发生/不得揭示”为硬边界；小说中间稿负责具体剧情设计，剧本阶段负责转写为可拍摄格式。
