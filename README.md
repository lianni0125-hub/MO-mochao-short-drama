# 🌊 墨潮 · AI 短剧自动编剧系统

> 从一句灵感，到可导出的小说与可拍摄短剧剧本。把“灵感—策划—人设—分集梗概—小说中间稿—剧本—跨集记忆”组织成一条可审批、可编辑、可续跑的本地创作流水线。

## ✨ 项目亮点

- 🎬 **完整 01–06 创作链**：灵感孵化、故事策划、人物人设、卡点与硬约束、分集梗概、小说与剧本。
- 🧠 **项目级剧情记忆**：向量剧情链、最近事件、人物关系、次要人物、时间脉络、金手指、重要道具与资源账本。
- 🔥 **短剧情绪与节奏设计**：普通/下沉剧情模式、强烈/异常强烈情绪、第一/第三人称和“必须发生/不得揭示”硬边界。
- 🧵 **分层写作**：小说中间稿完成剧情设计，再组织剧情安排并转换为可拍摄剧本；每一步均可检查、保存和重试。
- ⚙️ **长任务可靠运行**：后台任务、阶段检查点、自动继续、手动续跑、跨项目并行工作台与动态并发控制。
- 🔌 **多模型可接入**：MiniMax、OpenAI、智谱、DeepSeek、通义千问、Kimi 及 OpenAI-compatible API；Embedding 独立配置。
- 📚 **灵感资料库**：Reality 现实素材与 Market 平台趋势，支持公开来源更新、RSS、手动资料及 RAG 召回。
- 📄 **专业模板与 DOCX 工作流**：自带默认专业短剧、知乎盐选（漫剧）两套模板，也可分析并复核上传模板；支持按集导出梗概、小说或剧本。
- 🔐 **数据自主保存**：创作内容与 API 配置默认保存在当前设备或部署实例中，系统不会主动上传至项目作者或公共代码仓库。
- 💾 **跨设备备份恢复**：在模型设置中导出 `.mo-backup` 工作区备份，在新设备选择或拖入即可恢复；API Key 不进入备份。

## 🗺️ 创作流程

1. **灵感孵化**：从种子灵感与可选资料库中形成方向。
2. **故事策划**：标题、框架、世界观、故事梗概、核心期待。
3. **人物人设**：生成、补全、编辑人物，并可上传或生成形象参考。
4. **卡点与硬约束**：约束指定集数范围内的分集规划。
5. **分集梗概**：本集内容、集尾钩子、必须发生、不得揭示和主要人物首次出场规划。
6. **分级写作**：小说中间稿 → 剧情安排 → 可拍摄剧本 → 剧情记忆提炼。

不熟悉 Node.js 或 Git 的用户，可前往 [GitHub Releases](https://github.com/lianni0125-hub/MO-mochao-short-drama/releases/latest) 下载最新版：

```text
MO-mochao-Windows-v版本号.zip
```

完整解压后双击 **“启动墨潮.bat”** 即可，无需安装 Node.js，也无需执行命令。请勿在压缩软件中直接运行。便携版同样会自动检测新版本，并通过 GitHub Release 安全更新；`data/` 与 `.env` 始终保留。

## 🚀 从源码启动

要求 Node.js 25 或更高版本（项目使用 Node 内置 SQLite）。

```powershell
git clone https://github.com/lianni0125-hub/MO-mochao-short-drama.git
cd MO-mochao-short-drama
npm install
Copy-Item .env.example .env
npm start
```

项目默认监听 `0.0.0.0:6008`。启动后访问 <http://127.0.0.1:6008>。

如需改用仅本机可访问的 3210 端口，可在 `.env` 中设置：

```dotenv
PORT=3210
HOST=127.0.0.1
```

修改后重新启动服务，并访问 <http://127.0.0.1:3210>。端口与 API 配置保存在当前环境中，正常更新程序时不会被覆盖。

## ☁️ AutoDL 部署

项目已适配 AutoDL 的 6008 WebUI 端口，无需 GPU，使用 CPU 无卡实例即可运行。

### 从应用广场使用

镜像通过 AutoDL 应用广场审核后，可进入 **AI应用 → 应用广场**，搜索“墨潮 · AI 短剧自动编剧系统”并创建实例。镜像已经包含 Node.js 运行环境、项目源码和依赖。

### 从源码部署

```bash
cd /root
git clone https://github.com/lianni0125-hub/MO-mochao-short-drama.git
cd /root/MO-mochao-short-drama
npm install
cp .env.example .env
npm run start:autodl
```

服务默认监听 `0.0.0.0:6008`。在 AutoDL 实例页面打开对应的“自定义服务”地址即可访问。

### 开机自动启动

发布应用或创建部署时，请在 AutoDL 的“启动命令”中填写：

```bash
bash /root/MO-mochao-short-drama/scripts/autodl-start.sh
```

如果项目安装在其他目录，请将路径替换为实际仓库路径。启动脚本会自动定位项目根目录、加载 NVM 中的 Node.js，并以前台进程监听 `0.0.0.0:6008`。实例关机后任务停止；再次开机时，AutoDL 会重新执行启动命令。

## 🔑 配置模型

启动后可在“模型设置”中分别配置正文生成 API 与 Embedding API。两套配置互相独立：

- 正文生成支持 MiniMax、OpenAI、智谱、DeepSeek、通义千问、Kimi 及兼容接口。
- Embedding 用于剧情记忆建库和语义召回。
- 未配置 Embedding 时，策划、人设、模板、保存和导出仍可使用；涉及向量记忆的流程会提示完成配置。

## 💾 数据安全

| 内容 | 默认位置 | 源码更新是否包含 |
|---|---|---|
| 项目、正文、任务、剧情记忆 | `data/short-drama.db` | 不包含，保留现有数据 |
| 导入与导出文件 | `data/uploads/`、`data/exports/` | 不包含，保留现有文件 |
| API 配置 | `.env` | 不包含，保留现有配置 |
| 程序功能与公开资源 | 项目源码 | 包含 |

正常版本更新只替换程序文件，不会主动覆盖项目、正文、任务记录、剧情记忆或 API 配置。迁移设备、重建部署实例或更换镜像前，建议在“模型设置 → 备份与恢复”导出工作区备份，并单独妥善保管 `.env`。

通过公网部署时，请妥善保管应用访问地址；需要多人使用或公开提供服务时，建议在应用外层增加访问认证。

## 🔄 版本更新

应用会自动检查 GitHub 上的最新版本。发现更新后，左下角按钮会变为红色 **“版本更新！”**；点击即可查看版本号和更新内容，并可直接执行安全更新。系统会自动识别当前是 Git 安装版还是 Windows 便携版。

版本检查会依次尝试 GitHub Raw、GitHub API 和 jsDelivr，在部分网络通道暂时不可用时自动切换。

检查失败后会每30秒自动重试；网络恢复或页面重新回到前台时也会立即检查。成功后恢复为每30分钟检查一次，避免频繁请求版本服务。

暂时不想更新时，可以选择“忽略此版本”，红色提醒会恢复为普通状态；以后发布更高版本时，更新提醒会自动重新出现。

- **Git 安装版**：从本项目官方仓库快进合并并安装依赖；存在未提交源码修改时停止更新，完成后提示重启。
- **Windows 便携版**：从官方 GitHub Release 下载对应版本，校验 SHA-256 后建立恢复点并替换程序，随后自动重启。

两种方式在存在运行中任务时都会停止更新，也都不会覆盖 `data/`、`.env`、本地项目、创作内容或 API Key。
